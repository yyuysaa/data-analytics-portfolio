# Requirements: PRESENT Core Loop

## Overview

PRESENT is a personal accountability app. This spec covers the minimal core loop: the user schedules one activity, receives a warm AI-style nudge notification at the scheduled time, taps to check in with a photo, and builds a streak.

---

## Functional Requirements

### FR-1: Add a Scheduled Activity
- **FR-1.1:** The user can enter an activity name (free-text, e.g. "Data Science class").
- **FR-1.2:** The user can pick a time for the activity (hour and minute, today's date assumed).
- **FR-1.3:** The user can save the activity; it persists across app restarts (stored locally via AsyncStorage).
- **FR-1.4:** Only one activity needs to be supported at a time. Saving a new activity replaces the previous one.

### FR-2: Local Notification with AI Nudge
- **FR-2.1:** At the scheduled time, the app fires a local push notification.
- **FR-2.2:** The notification body contains an encouraging nudge message that references the activity name.
- **FR-2.3:** The nudge text is generated by a function `generateNudge(activityName)` which currently picks from a hardcoded list of warm messages.
- **FR-2.4:** The `generateNudge` function is isolated in its own file so it can be swapped for a real AI API call later.

### FR-3: Camera Check-In
- **FR-3.1:** Tapping the notification opens the app to a camera screen.
- **FR-3.2:** The user can take a single photo using the device camera.
- **FR-3.3:** The photo is saved to the device's local media library only (no upload, no cloud).
- **FR-3.4:** After saving, the user is returned to the home screen.

### FR-4: Streak Counter (Consecutive Days)
- **FR-4.1:** A streak is measured in consecutive **days**, not per check-in.
- **FR-4.2:** Completing at least one photo check-in on a given calendar day counts that day as "done" (Duolingo-style — one action keeps the streak alive).
- **FR-4.3:** If the user checks in today and also checked in yesterday, the streak increases by 1. The first check-in after a gap starts the streak at 1.
- **FR-4.4:** If a full calendar day passes with zero check-ins, the streak resets to 0.
- **FR-4.5:** Multiple check-ins in the same day do NOT increase the streak more than once — the day is either done or not.
- **FR-4.6:** The current streak count and the date of the last check-in are stored locally via AsyncStorage and persist across app restarts.

---

## Non-Functional Requirements

### NFR-1: Simplicity
- The codebase must be beginner-readable with comments explaining each part.
- Minimal error handling — just enough to not crash.
- No test suite required in this iteration.

### NFR-2: Technology Stack
- React Native with Expo (managed workflow).
- `expo-notifications` for local notifications.
- `expo-camera` for the camera screen.
- `@react-native-async-storage/async-storage` for local persistence.
- `expo-media-library` for saving photos to the device.

### NFR-3: No Backend
- No server, no API calls, no user accounts, no cloud storage.
- Everything runs and persists on-device only.

---

## Out of Scope
- Multiple activities / full daily schedule builder.
- Real AI API integration (placeholder only).
- Social feed / "life story" feature.
- User accounts, login, or cloud sync.
- Android-specific adjustments (iOS-first for now, but Expo keeps it cross-platform by default).

## Planned Future Features (not built in this spec)
- **Streak Freeze:** A consumable item that absorbs one missed day so the streak survives (for emergencies). The streak logic in this spec should be structured so a freeze can be added later without a rewrite (e.g. the "should reset?" check is in one clear place).
